# AI Text Summarizer

A minimal FastAPI service with one real endpoint (`POST /summarize`) that
sends text to an LLM and returns a summary. Built to practice: FastAPI
basics, Pydantic request/response models, error handling, API testing,
and wiring up an LLM (OpenAI-compatible or local Ollama).

## Project structure

```
ai-text-summarizer/
├── app/
│   ├── main.py              # FastAPI app + /summarize route
│   ├── config.py            # env-based settings (pydantic-settings)
│   ├── schemas.py           # Pydantic request/response models
│   └── services/
│       └── summarizer.py    # LLM call logic (OpenAI or Ollama)
├── tests/
│   └── test_main.py         # pytest tests, LLM call is mocked
├── requirements.txt
├── .env.example
└── README.md
```

## 1. Setup (Windows, PowerShell)

```powershell
cd path\to\ai-text-summarizer

python -m venv .venv
.venv\Scripts\activate

pip install -r requirements.txt

copy .env.example .env
```

## 2. Choose your LLM provider

Open `.env` and set `LLM_PROVIDER` to one of:

**Option A — Ollama (free, runs locally, no API key needed)**
1. Install Ollama: https://ollama.com/download
2. Pull a small model: `ollama pull llama3.2`
3. Make sure it's running (`ollama serve` — usually auto-starts)
4. In `.env`: `LLM_PROVIDER=ollama`

**Option B — OpenAI or any OpenAI-compatible API (Groq, Grok/xAI, etc.)**
1. In `.env`: `LLM_PROVIDER=openai`
2. Set `OPENAI_API_KEY=your-key`
3. Set `OPENAI_BASE_URL` if not using real OpenAI (e.g. Grok's endpoint)
4. Set `OPENAI_MODEL` to a model your provider supports

## 3. Run the server

```powershell
uvicorn app.main:app --reload
```

Server runs at `http://127.0.0.1:8000`.
Interactive docs (auto-generated by FastAPI) at `http://127.0.0.1:8000/docs`.

## 4. Try it

**Via the /docs UI** — open it in a browser, expand `POST /summarize`, click
"Try it out", paste text, execute.

**Via curl:**
```powershell
curl -X POST http://127.0.0.1:8000/summarize `
  -H "Content-Type: application/json" `
  -d '{\"text\": \"FastAPI is a modern Python web framework for building APIs quickly, with automatic docs and validation.\", \"max_words\": 20}'
```

**Response:**
```json
{
  "summary": "FastAPI is a modern Python framework for quickly building APIs, with built-in validation and auto-generated documentation.",
  "original_length_words": 18,
  "summary_length_words": 16
}
```

## 5. Run the tests

```powershell
pytest tests/ -v
```

Tests mock the LLM call, so they run instantly with no API key or Ollama
needed — this is what "API testing" means in practice: you test your
FastAPI layer (validation, routing, error handling) independently of
whether the LLM itself is up.

## Design notes / why it's built this way

- **Pydantic models** (`schemas.py`) validate input before it ever reaches
  your business logic — try posting `{"text": ""}` and you'll get a 422,
  not a crash.
- **Service layer separation**: `summarizer.py` knows nothing about HTTP;
  `main.py` knows nothing about LLM SDKs. This makes both independently
  testable and swappable (e.g. swap Ollama for OpenAI by changing `.env`,
  zero code changes).
- **502 vs 500**: if the LLM provider fails, that's a failure of an
  upstream dependency, not a bug in your API — hence `HTTPException(502)`
  instead of letting it bubble up as an unhandled 500.
- **Ollama uses the OpenAI SDK too**: Ollama exposes an OpenAI-compatible
  `/v1/chat/completions` endpoint, so one client class (`openai.OpenAI`)
  handles both providers — just point `base_url` at a different place.

## Next steps to extend this project

- Add streaming responses (`stream=True`) so the summary appears token
  by token — good practice for FastAPI's `StreamingResponse`.
- Add a `/summarize/file` endpoint that accepts a `.txt` or `.pdf` upload.
- Add rate limiting (`slowapi`) since LLM calls cost money/time.
- Containerize with Docker so it's a portable deployable artifact for
  your GitHub portfolio.
